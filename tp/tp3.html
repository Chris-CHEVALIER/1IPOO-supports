TP3 – L'arène

1IPOO – Projet fil rouge « Les Chroniques d'Ardelune » · Mercredi 2 décembre

Contexte

Pour choisir ceux qui partiront affronter la brume grise, la guilde organise un grand tournoi dans l'arène d'Ardelune. Guerriers, mages et paladins s'y affrontent tous ensemble, chacun à son tour, jusqu'à ce qu'il n'en reste qu'un.

L'arène ne connaît que des « héros ». Pourtant, chaque combattant doit agir selon sa classe : le guerrier entre en rage, le mage lance ses sorts… C'est exactement ce que permet le polymorphisme. 🏟️

Ce TP en bref
  • Objectifs : utiliser des méthodes virtuelles, transformer Hero en classe abstraite et manipuler une collection d'objets de types différents.
  • Vous continuez dans le même dépôt. Ce TP termine le projet que vous présenterez en soutenance le 15 décembre (dernier commit à 11h00).
  • Un commit et un push à chaque étape terminée.

1 Les méthodes virtuelles

virtual · override · destructeur virtuel

L'énigme du TP2 vient de la résolution statique : playTurn reçoit des Hero&, donc le compilateur appelle toujours les méthodes de Hero. Corrigez-la :

  1. dans Hero.hpp, ajoutez virtual devant attack, display et le destructeur ~Hero() ;
  2. ajoutez override à la fin des méthodes qui les redéfinissent : attack dans Warrior.hpp, display dans Mage.hpp et Paladin.hpp ;
  3. relancez votre programme du TP2 : pendant le duel, Brom entre maintenant en rage et le mana d'Aria s'affiche.

      #include "Mage.hpp"
      #include "Warrior.hpp"

      // Fonctions qui ne connaissent que la classe Hero.
      void strike(const Hero& attacker, Hero& target) {
          attacker.attack(target);
      }

      void show(const Hero& hero) {
          hero.display();
      }

      int main() {
          Warrior brom("Brom", Weapon("Hache de guerre", 15));
          Mage aria("Aria", Weapon("Bâton runique", 6));
          brom.takeDamage(70);
          strike(brom, aria);
          show(aria);
          return 0;
      }
    
Brom frappe Aria avec Hache de guerre : 15 dégâts.
Brom entre en rage : 5 dégâts de plus !
Aria – 60/80 PV – 3 potion(s) – Bâton runique (6 dégâts)
   Mana : 60/60
Aria quitte l'aventure.
Brom quitte l'aventure.
Indices
  • virtual et override s'écrivent seulement dans les .hpp, pas dans les .cpp.
  • Une faute de frappe dans le nom d'une méthode marquée override provoque une erreur de compilation : c'est voulu, elle vous protège.
  • Le destructeur virtuel garantit que la partie fille d'un héros est bien détruite, même à travers un pointeur Hero*.
Pour valider, assurez-vous que…
  • le programme d'essai affiche exactement les lignes attendues ;
  • dans le duel du TP2, Brom entre en rage quand il a moins de 65 PV ;
  • vous avez fait un commit « Méthodes virtuelles » et vous l'avez poussé.

2 La classe abstraite

Méthodes virtuelles pures · classe abstraite

Dans l'arène, chaque héros a une capacité spéciale propre à sa classe. Un « héros en général » n'en a pas : Hero devient abstraite.

  1. Ajoutez à Hero deux méthodes virtuelles pures :
    • virtual bool useSpecial(Hero& target) = 0; : utilise la capacité spéciale sur la cible, renvoie false si elle est refusée ;
    • virtual std::string getClassName() const = 0; : renvoie le nom de la classe en français.
  2. Modifiez Hero::display() pour afficher la classe après le nom : Aria [Mage] – 80/80 PV – …
  3. Écrivez ces deux méthodes dans chaque classe fille, avec override :
ClassegetClassName()Capacité spéciale useSpecial(target)
Warrior"Guerrier"Coup puissant : le guerrier perd 10 PV et inflige le double des dégâts de son arme. Brom porte un coup puissant à Aria : 30 dégâts (et perd 10 PV). Refusé s'il a 10 PV ou moins : Brom est trop affaibli pour un coup puissant !
Mage"Mage"Boule de feu : appelle simplement castFireball(target)
Paladin"Paladin"Châtiment sacré : 15 de mana, inflige 15 dégâts à la cible et rend 15 PV au paladin. Elwin lance un châtiment sacré sur Brom : 15 dégâts, et regagne 15 PV. Sans assez de mana : Elwin n'a plus assez de mana !

      #include "Mage.hpp"
      #include "Paladin.hpp"
      #include "Warrior.hpp"
      #include <vector>
      using namespace std;

      int main() {
          Warrior brom("Brom", Weapon("Hache de guerre", 15));
          Mage aria("Aria", Weapon("Bâton runique", 6));
          Paladin elwin("Elwin", Weapon("Marteau sacré", 10));
          Warrior dummy("Mannequin", Weapon());
          vector<Hero*> heroes = {&brom, &aria, &elwin};

          for (Hero* hero : heroes) {
              hero->useSpecial(dummy);
          }
          for (Hero* hero : heroes) {
              hero->display();
          }
          dummy.display();
          return 0;
      }

Indices
  • Hero::display() peut appeler getClassName() alors que Hero ne l'écrit pas : à l'exécution, c'est la version de la vraie classe de l'objet qui est appelée.
  • Paladin hérite de Warrior : sans redéfinition, il serait « Guerrier » avec un coup puissant. Il doit donc redéfinir les deux méthodes.
  • Les programmes d'essai du TP2 qui créent un Hero ne compilent plus : c'est normal, on ne peut plus créer d'objet d'une classe abstraite.
Pour valider, assurez-vous que…
  • le programme d'essai affiche exactement les lignes attendues ;
  • la ligne Hero test("Test", 100, Weapon()); dans main provoque une erreur de compilation (essayez, puis retirez-la) ;
  • vous avez fait un commit « Hero abstraite » et vous l'avez poussé.

3 L'arène

vector · pointeurs · polymorphisme

Créez la classe Arena dans Arena.hpp et Arena.cpp. Elle range des pointeurs vers les combattants : elle ne les copie pas, elle sait seulement où les trouver.

ÉlémentRôle
std::vector<Hero*> fighters privéles combattants inscrits
void addFighter(Hero* hero)inscrit un combattant (ignore nullptr)
int countAlive() constnombre de combattants encore en vie
void displayFighters() constaffiche tous les combattants
Hero* chooseTarget(const Hero* active) const privérenvoie la cible du héros actif, parmi les autres combattants en vie. S'il n'en reste qu'un, elle le renvoie directement. Sinon, elle affiche Cibles : [1] Brom [2] Elwin et redemande tant que le numéro est invalide
void playTurn(Hero* active) privéjoue le tour d'un héros : [1] Attaquer [2] Capacité spéciale [3] Boire une potion. Redemande tant que le choix est invalide ou que l'action est refusée. Si la cible n'a plus de PV : Brom tombe au combat !
void fight()affiche les combattants, puis fait jouer chaque héros vivant à son tour, manche après manche, jusqu'à ce qu'il n'en reste qu'un. Annonce enfin le vainqueur

Déplacez la fonction readChoice() du TP1 au début de Arena.cpp : seule l'arène lit des saisies.

Indices
  • Parcourir les combattants : for (Hero* hero : fighters) { … }. Appeler une méthode à travers un pointeur : hero->isAlive().
  • attack et useSpecial attendent une référence : passez *target (l'objet pointé par target).
  • Pour construire la liste des cibles, créez un vector<Hero*> local et ajoutez-y chaque héros vivant différent de active.
  • Dans fight(), vérifiez countAlive() > 1 avant chaque tour : le combat peut se terminer au milieu d'une manche.
Pour valider, assurez-vous que…
  • Arena ne mentionne jamais Warrior, Mage ni Paladin : elle ne connaît que Hero ;
  • Arena.cpp se compile sans avertissement ;
  • vous avez fait un commit « Classe Arena » et vous l'avez poussé.

4 Le tournoi

Synthèse

Le main.cpp final crée trois héros, les inscrit dans l'arène et lance le combat :


      #include "Arena.hpp"
      #include "Mage.hpp"
      #include "Paladin.hpp"
      #include "Warrior.hpp"

      int main() {
          Mage aria("Aria", Weapon("Bâton runique", 6));
          Warrior brom("Brom", Weapon("Hache de guerre", 15));
          Paladin elwin("Elwin", Weapon("Marteau sacré", 10));

          Arena arena;
          arena.addFighter(&aria);
          arena.addFighter(&brom);
          arena.addFighter(&elwin);
          arena.fight();
          return 0;
      }

Facultatif

Bonus 1 – Choisir ses combattants

  • Au lancement, demandez le nombre de combattants, puis le nom et la classe de chacun.
  • Les héros sont alors créés avec new : pensez à les détruire avec delete à la fin, ou mieux, utilisez std::unique_ptr.

Bonus 2 – Des adversaires automatiques

  • Ajoutez une méthode virtuelle chooseAction() : un héros contrôlé par l'ordinateur choisit seul son action et sa cible (le plus faible, par exemple).

Bonus 3 – Une quatrième classe

  • Ajoutez l'Archer du TP2 à l'arène : il lui suffit d'écrire useSpecial et getClassName. Constatez que la classe Arena n'a pas besoin d'être modifiée.
