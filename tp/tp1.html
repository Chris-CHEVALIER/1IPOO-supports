TP1 – Les premiers héros

1IPOO – Projet fil rouge « Les Chroniques d'Ardelune » · Mardi 1er décembre

Contexte

Le royaume d'Ardelune vivait en paix depuis des siècles. Mais depuis la dernière pleine lune, une brume grise descend des montagnes et réveille des créatures oubliées. Les villages appellent à l'aide des aventuriers prêts à défendre le royaume.

Avant de les envoyer au combat, la guilde des aventuriers veut tester ses recrues lors de duels d'entraînement. Votre mission : écrire en C++ le programme qui gère ces héros, leurs armes et leurs duels. ⚔️

Ce TP en bref
  • Objectifs : écrire deux classes réparties en fichiers .hpp et .cpp, protéger leurs données (encapsulation), utiliser des constructeurs, un destructeur et des références.
  • Ce TP est la première brique du projet Ardelune, que vous enrichirez au TP2 et au TP3 puis présenterez en soutenance le 15 décembre.
  • Faites un commit et poussez-le sur GitHub à chaque étape terminée.
  • L'IA est autorisée pour le projet, à une condition : comprendre chaque ligne de votre code. Je le vérifierai en soutenance.

1 Les armes

Classe · encapsulation · constructeurs · .hpp et .cpp

Chaque héros porte une arme. Une arme a un nom et un nombre de dégâts.

Créez la classe Weapon dans deux fichiers, Weapon.hpp et Weapon.cpp :

ÉlémentRôle
std::string name privénom de l'arme
int damage privédégâts infligés, toujours entre 1 et 50
Weapon()constructeur par défaut : un "Bâton de marche" de 5 dégâts
Weapon(std::string newName, int newDamage)constructeur avec paramètres. Une valeur de dégâts inférieure à 1 devient 1, une valeur supérieure à 50 devient 50
std::string getName() constrenvoie le nom
int getDamage() constrenvoie les dégâts
void display() constaffiche Épée courte (12 dégâts) puis passe à la ligne

Pour tester votre classe, remplacez le contenu de main.cpp par ce programme d'essai :


      #include "Weapon.hpp"

      int main() {
          Weapon stick;
          Weapon sword("Épée courte", 12);
          Weapon legendary("Lame du dragon", 999);
          stick.display();
          sword.display();
          legendary.display();
          return 0;
      }
    
Bâton de marche (5 dégâts)
Épée courte (12 dégâts)
Lame du dragon (50 dégâts)
Indices
  • Le .hpp commence par #pragma once et #include <string>. Il ne contient que les attributs et les prototypes.
  • Le .cpp commence par #include "Weapon.hpp". Chaque méthode y est précédée de Weapon::.
  • Le constructeur peut d'abord recopier newDamage grâce à la liste d'initialisation, puis corriger la valeur avec deux if dans son corps.
  • const s'écrit dans le .hpp et dans le .cpp.
Pour valider, assurez-vous que…
  • les attributs sont privés et la classe se compile sans avertissement ;
  • le programme d'essai affiche exactement les trois lignes attendues ;
  • vous avez fait un commit « Classe Weapon » et vous l'avez poussé.

2 Les héros

Composition · constructeur · destructeur · méthodes const

Un héros a un nom, des points de vie (PV), des potions et une arme. Créez la classe Hero dans Hero.hpp et Hero.cpp :

ÉlémentRôle
std::string name privénom du héros
int health privéPV actuels, jamais négatifs ni supérieurs à maxHealth
int maxHealth privéPV maximum, entre 50 et 200
int potions privénombre de potions, 3 au départ
Weapon weapon privél'arme équipée : un objet de la classe Weapon
Hero(std::string newName, int newMaxHealth, Weapon newWeapon)constructeur. maxHealth est ramené entre 50 et 200, puis le héros commence avec tous ses PV et 3 potions
~Hero()destructeur : affiche Aria quitte l'aventure.
std::string getName() const et int getHealth() constaccesseurs
bool isAlive() constrenvoie true si le héros a encore des PV
void takeDamage(int amount)retire amount PV, sans descendre sous 0. Une valeur négative est ignorée
void display() constaffiche Aria – 70/100 PV – 3 potion(s) – puis l'arme, grâce à sa méthode display()

      #include "Hero.hpp"
      #include <iostream>
      using namespace std;

      int main() {
          Hero aria("Aria", 100, Weapon("Épée courte", 12));
          Hero golem("Golem", 500, Weapon());
          aria.display();
          golem.display();

          aria.takeDamage(30);
          aria.display();
          aria.takeDamage(-10);
          aria.takeDamage(200);
          cout << aria.getHealth() << " " << aria.isAlive() << endl;
          return 0;
      }
    
Aria – 100/100 PV – 3 potion(s) – Épée courte (12 dégâts)
Golem – 200/200 PV – 3 potion(s) – Bâton de marche (5 dégâts)
Aria – 70/100 PV – 3 potion(s) – Épée courte (12 dégâts)

Golem quitte l'aventure.
Aria quitte l'aventure.
Indices
  • Hero.hpp doit inclure "Weapon.hpp" : sans lui, le compilateur ne connaît pas le type Weapon.
  • L'arme s'initialise dans la liste d'initialisation, comme les autres attributs : weapon(newWeapon).
  • Weapon("Épée courte", 12) crée une arme sans lui donner de nom de variable, juste pour la passer au constructeur.
  • Pourquoi « Golem quitte l'aventure. » s'affiche-t-il avant Aria ? Revoyez l'ordre de destruction des objets à la fin d'un bloc.
Pour valider, assurez-vous que…
  • le programme d'essai affiche exactement les six lignes attendues ;
  • aucun attribut n'est public et toutes les méthodes qui ne modifient pas le héros sont const ;
  • vous avez fait un commit « Classe Hero » et vous l'avez poussé.

3 Les actions

Références · objets qui collaborent

Ajoutez trois méthodes à la classe Hero :

MéthodeRôle
void attack(Hero& target) constaffiche Brom frappe Aria avec Hache de guerre : 15 dégâts. puis inflige à target les dégâts de l'arme
bool drinkPotion()consomme une potion et rend 30 PV, sans dépasser maxHealth. Affiche Aria boit une potion : 100/100 PV. et renvoie true.
Refuse et renvoie false s'il ne reste aucune potion (Aria n'a plus de potion !) ou si le héros a déjà tous ses PV (Aria est déjà en pleine forme.). Une potion refusée n'est pas consommée
void equip(Weapon newWeapon)remplace l'arme du héros et affiche Aria s'équipe : Arc long.

      #include "Hero.hpp"

      int main() {
          Hero aria("Aria", 100, Weapon("Épée courte", 12));
          Hero brom("Brom", 120, Weapon("Hache de guerre", 15));
          brom.attack(aria);
          aria.drinkPotion();
          aria.drinkPotion();
          aria.equip(Weapon("Arc long", 18));
          aria.attack(brom);
          brom.display();
          return 0;
      }

Aria boit une potion : 100/100 PV.

Brom – 102/120 PV – 3 potion(s) – Hache de guerre (15 dégâts)

Indices
  • target est une référence : target.takeDamage(…) modifie le vrai héros adverse, pas une copie.
  • attack peut être const : elle modifie la cible, pas le héros qui attaque.
  • Les dégâts se lisent avec l'accesseur de l'arme : weapon.getDamage(). Les attributs de Weapon restent privés.
Pour valider, assurez-vous que…
  • le programme d'essai affiche exactement les huit lignes attendues ;
  • une potion refusée n'est pas consommée ;
  • vous avez fait un commit « Actions des héros » et vous l'avez poussé.

4 Le duel

Fonctions · boucles · saisies · références

Remplacez le programme d'essai par le vrai jeu. Dans main.cpp :

  1. Créez deux héros : Aria (100 PV, « Épée courte », 12 dégâts) et Brom (120 PV, « Hache de guerre », 15 dégâts).
  2. Écrivez une fonction void playTurn(Hero& active, Hero& opponent), au-dessus de main. Elle joue le tour du héros active :
    • elle affiche --- Tour : Aria --- puis l'état du héros ;
    • elle propose [1] Attaquer [2] Boire une potion et lit le choix avec cin ;
    • elle redemande tant que le choix est invalide : autre nombre, lettres, potion refusée.
  3. Dans main, les héros jouent chacun leur tour tant qu'ils sont tous les deux en vie. À la fin, affichez le vainqueur : Brom tombe au combat ! Aria remporte le duel.

Quand l'utilisateur tape des lettres au lieu d'un nombre, cin passe en état d'erreur et refuse toutes les lectures suivantes. Cette fonction lit un choix sans planter. Copiez-la au-dessus de playTurn :


      // Lit un entier au clavier ; renvoie -1 si la saisie n'est pas un nombre.
      int readChoice() {
          int choice;
          if (!(cin >> choice)) {
              cin.clear();             // efface l'état d'erreur de cin
              cin.ignore(1000, '\n');  // jette le reste de la ligne tapée
              return -1;
          }
          return choice;
      }
Indices
  • Pour alterner les joueurs, comptez les tours : un tour impair pour Aria (playTurn(aria, brom)), un tour pair pour Brom (playTurn(brom, aria)). turn % 2 donne le reste de la division par 2.
  • Dans playTurn, une boucle while (true) qui se termine par un return dès qu'une action a réussi fait très bien l'affaire.
  • Si « Aria quitte l'aventure. » s'affiche au milieu du duel, un héros a été passé par copie : la copie est détruite à la fin de la fonction. Vérifiez les &.
Pour valider, assurez-vous que…
  • un duel complet se joue jusqu'à la victoire d'un des deux héros ;
  • aucune saisie ne fait planter ou boucler le programme : lettres, 0, 7, potion refusée… ;
  • les messages « quitte l'aventure » n'apparaissent qu'à la toute fin ;
  • vous avez fait un commit « Duel » et vous l'avez poussé.

+ Pour aller plus loin

Facultatif

Bonus 1 – Choisir son héros

  • Au lancement, chaque joueur saisit le nom de son héros et choisit son arme dans une liste de trois armes.

Bonus 2 – Coups critiques

  • Chaque attaque a une chance sur cinq d'infliger le double des dégâts : Coup critique !
  • Pour tirer un nombre au hasard, utilisez std::uniform_int_distribution de la bibliothèque <random>.

Bonus 3 – Un adversaire automatique

  • Ajoutez un mode « contre l'ordinateur » : Brom choisit seul son action. Il boit une potion s'il lui reste moins de 30 PV, sinon il attaque.
