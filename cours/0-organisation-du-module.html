Le module

Organisation du module

Pourquoi le C++ ?

Un langage rapide et proche de la machine :

  • Il est compilé : votre code est traduit en langage machine avant d'être lancé
  • Il est utilisé là où la performance compte : moteurs de jeux vidéo, navigateurs web, systèmes embarqués, finance
  • Il est normalisé et libre d'usage : plusieurs compilateurs gratuits existent (GCC, Clang)

Un langage pour apprendre l'objet :

  • Il rend visibles les notions que Python cache : types, droits d'accès, mémoire
  • Les concepts objet appris ici (classe, héritage, polymorphisme) se retrouvent en Java, C#, PHP, Python…
Vous savez déjà programmer en Python : variables, conditions, boucles et fonctions existent aussi en C++. Seule l'écriture change.
Rassurer : on ne repart pas de zéro. Le premier cours fait le pont Python → C++ avant de passer à l'objet.

Objectifs du module

À l'issue du module, vous serez capables de :

  • Écrire, compiler et exécuter un programme C++ réparti en plusieurs fichiers
  • Créer des classes avec des attributs, des méthodes, des constructeurs et un destructeur
  • Protéger les données d'un objet grâce à l'encapsulation
  • Réutiliser du code grâce à l'héritage, simple et multiple
  • Manipuler une collection d'objets différents grâce au polymorphisme et aux classes abstraites

Programme

Cours 1 – Classes et objets

Du Python au C++, classes, attributs et méthodes, encapsulation, fichiers .hpp et .cpp, constructeurs et destructeur

Cours 2 – Héritage et polymorphisme

Héritage simple et multiple, méthodes virtuelles, collections d'objets, classes abstraites

Projet fil rouge « Les Chroniques d'Ardelune »

3 TP qui s'enchaînent : un jeu de rôle en mode texte, construit étape par étape, des premiers héros jusqu'à une arène de combat

La soutenance et l'écrit portent sur ce que vous démontrez vous-mêmes, en direct.
Justifier : à l'heure de l'IA générative, un code rendu ne prouve pas qu'on sait programmer. La soutenance et l'écrit vérifient la compréhension.

Soutenance et examen écrit

Soutenance individuelle · 10 min · le 15/12 dès 11h00

  • Démonstration de votre jeu
  • Explication d'une partie du code que je choisis
  • Une petite modification en direct, sans IA

Examen écrit · 30 min · le 15/12 à 14h45

  • Questions ouvertes sur les deux cours
  • Plusieurs questions portent sur des extraits de code à lire
  • Sur ordinateur (questionnaire Microsoft Forms), avec votre compte École Hexagone
  • Sans documents ni IA. Tiers temps : 40 min

Rendu du projet sur GitHub

  • Un dépôt privé nommé 1ipoo-ardelune-nom-prenom, créé avec GitHub Desktop
  • Invitez Chris-CHEVALIER comme collaborateur dès le mardi 1er décembre
  • Des commits réguliers, au moins un par étape terminée
  • Un README.md qui explique comment compiler et lancer le jeu et qui déclare votre usage de l'IA
Rendu du projet complet au plus tard le mardi 15 décembre à 11h00 : le dernier commit poussé avant cette heure fait foi.

GitHub appartient à Microsoft et relève du droit américain (Cloud Act). Je l'utilise parce que je le maîtrise. Des alternatives ouvertes existent : GitLab, Codeberg.

L'IA générative : autorisée, à une condition

  • ChatGPT, Claude, Copilot… sont autorisés pour le projet
  • Vous devez comprendre votre code de bout en bout. Chaque ligne rendue doit pouvoir être expliquée
  • Déclarez votre usage dans le README : quels outils, pour quoi faire
  • La soutenance vérifie cette compréhension. Une fonctionnalité non expliquée n'est pas comptée
  • Soutenance et examen se font sans IA
  • L'entraide est encouragée. Expliquer, oui ; donner son code, non
Conseil : utilisez l'IA comme un tuteur (expliquer une erreur de compilation, relire votre code), pas comme un auteur.
