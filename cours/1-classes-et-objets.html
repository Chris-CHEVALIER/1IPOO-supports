Compiler plutôt qu'interpréter

1. Écrire
Vous écrivez le code source dans un fichier .cpp
2. Compiler
Le compilateur g++ vérifie le code et le traduit en langage machine
3. Obtenir
Un programme exécutable : hello (hello.exe sous Windows)
4. Exécuter
Vous lancez ce programme autant de fois que vous voulez, sans recompiler

Python : interprété

L'interpréteur lit et exécute votre fichier ligne après ligne. Une faute de frappe n'est découverte qu'au moment où la ligne s'exécute.

C++ : compilé

Le compilateur lit tout le fichier avant de produire le programme. La plupart des erreurs sont détectées avant même le lancement.
Insister : à chaque modification du code, il faut recompiler. Erreur classique : modifier le .cpp et relancer l'ancien exécutable.

#include <iostream>

  • #include <iostream> importe les outils d'affichage, comme import en Python
  • main() est la fonction principale : le programme commence toujours par elle
  • std::cout << affiche ce qui suit et std::endl passe à la ligne. std:: indique qu'ils viennent de la bibliothèque standard
  • Les accolades délimitent les blocs et chaque instruction finit par un point-virgule
  • -Wall affiche tous les avertissements (warnings) du compilateur : gardez-le toujours
Faire taper ce programme par tout le monde, compiler, exécuter. Puis retirer un point-virgule pour voir l'erreur.

Lire une erreur de compilation

Si le code contient une erreur, aucun programme n'est produit. Le compilateur indique :

  • le fichier, la ligne et la colonne (hello.cpp:4:40) ;
  • le problème (expected ';' : un point-virgule était attendu).
Une erreur peut en provoquer dix autres. Corrigez la première, recompilez, recommencez.

Classe et objet

  • Une classe est un modèle : elle décrit ce que contient un objet et ce qu'il sait faire
  • Un objet est un exemplaire concret créé à partir de ce modèle. C'est une instance de la classe
  • Une classe a des attributs (ses données) et des méthodes (ses actions : des fonctions de la classe)
  • Par convention, une classe commence par une majuscule (LibraryCard), un objet par une minuscule (manonCard)

La classe LibraryCard (carte de bibliothèque)

Attributs : le nom du titulaire, le nombre de livres empruntés

Méthodes : emprunter un livre, rendre un livre, afficher la carte

Objets : la carte de Manon, celle de Cosmo… Chacune a ses propres valeurs.

L'encapsulation

Classes et objets

Le problème des attributs publics

La bibliothèque limite les emprunts à 5 livres par carte. Mais rien n'empêche d'écrire n'importe quoi :

card.borrowedBooks = 42;
card.borrowedBooks = -3;

Le programme accepte ces valeurs absurdes. Chaque développeur qui utilise la classe doit penser à vérifier… et il finira par oublier.

Le principe d'encapsulation

Les attributs d'une classe sont cachés : on ne peut pas les modifier depuis l'extérieur.

On passe par des méthodes publiques, qui vérifient la cohérence des valeurs avant de modifier les attributs.

L'objet protège lui-même ses données.

Des méthodes qui protègent les données


#include <iostream>
using namespace std;

class LibraryCard {
private:
    int borrowedBooks = 0;

public:
    bool borrowBook() {
        if (borrowedBooks >= 5) {
            cout << "Limite atteinte." << endl;
            return false;
        }
        borrowedBooks++;
        return true;
    }

    int getBorrowedBooks() const {
        return borrowedBooks;
    }
};
        

int main() {
    LibraryCard card;
    for (int i = 0; i < 6; i++) {
        card.borrowBook();
    }
    cout << card.getBorrowedBooks() << endl;
    return 0;
}
          
Limite atteinte.
5
  • borrowBook() refuse le 6e emprunt et renvoie false
  • getBorrowedBooks() donne la valeur en lecture seule : on peut la lire, pas la modifier
  • = 0 après un attribut donne sa valeur de départ. Les constructeurs feront mieux

Accesseurs, mutateurs et méthodes const

private:
    int age;

public:
    int getAge() const {        // accesseur
        return age;
    }

    void setAge(int newAge) {   // mutateur
        if (newAge >= 15 && newAge <= 99) {
            age = newAge;
        }
    }
  • Un accesseur (getter) renvoie la valeur d'un attribut privé. Son nom commence par get
  • Un mutateur (setter) modifie un attribut après vérification. Son nom commence par set
  • const en fin de méthode promet qu'elle ne modifie pas l'objet. Le compilateur y refuse toute modification d'attribut
  • Pas de mutateur par réflexe : seulement s'il a du sens. On ne change pas le titulaire d'une carte

À vous : la classe Timetable

Dans un fichier timetable.cpp, écrivez une classe Timetable (emploi du temps de la semaine) :

  • un attribut privé hours (nombre d'heures de cours, 0 au départ) ;
  • une méthode addCourse(int duration) qui ajoute la durée seulement si elle est comprise entre 1 et 4 heures et si le total ne dépasse pas 35 heures. Elle renvoie true si le cours est ajouté, false sinon ;
  • un accesseur getHours() constant.

Dans main, ajoutez un cours de 3 h, un de 6 h (refusé) et un de 4 h, puis affichez le total : 7.

Correction : if (duration < 1 || duration > 4 || hours + duration > 35) return false; hours += duration; return true; Pour Versailles : un volontaire partage son écran pour montrer sa solution.

Constructeurs et destructeur

Classes et objets

Le constructeur

  • Le constructeur est appelé automatiquement à la création de chaque objet, comme __init__ en Python
  • Il porte le nom de la classe et n'a aucun type de retour, pas même void
  • Après les deux-points, la liste d'initialisation donne leur valeur de départ aux attributs
  • Sans constructeur, un attribut int contient une valeur imprévisible : une source de bugs classique en C++
LibraryCard(string newOwner)
    : owner(newOwner), borrowedBooks(0) {
}
LibraryCard manonCard("Manon");
LibraryCard cosmoCard("Cosmo");

Le constructeur en action

Plusieurs constructeurs

  • Une classe peut avoir plusieurs constructeurs avec des paramètres différents. C'est la surcharge
  • Le compilateur choisit le bon selon les arguments donnés à la création
  • Le constructeur sans paramètre est le constructeur par défaut. On crée l'objet sans parenthèses : LibraryCard guest;
  • Le constructeur vérifie les valeurs : l'objet est cohérent dès sa naissance

Séparer une classe en deux fichiers

Classes et objets

Un fichier pour déclarer, un pour définir

Dès qu'un programme grandit, chaque classe est répartie dans deux fichiers :

FichierContenuRôle
LibraryCard.hppla déclaration : attributs et prototypes des méthodesle « sommaire » de la classe, ce que les autres fichiers doivent connaître
LibraryCard.cppla définition : le code de chaque méthodele « comment ça marche »
main.cppla fonction mainle programme qui utilise la classe
Un prototype est la première ligne d'une fonction, sans son code : bool borrowBook();. .hpp vient de header (fichier d'en-tête).

Le fichier d'en-tête .hpp


#pragma once
#include <string>

class LibraryCard {
private:
    std::string owner;
    int borrowedBooks;

public:
    LibraryCard(std::string newOwner);
    bool borrowBook();
    bool returnBook();
    int getBorrowedBooks() const;
    void display() const;
};
  • On ne garde que les attributs et les prototypes, terminés par un point-virgule
  • #pragma once empêche que le fichier soit inclus deux fois dans un même programme, ce qui provoquerait l'erreur « classe déjà définie »
  • Pas de using namespace std; dans un .hpp : on écrit std::string
  • On lit ce fichier pour savoir ce que la classe sait faire
Pourquoi pas de using dans un .hpp : il s'imposerait à tous les fichiers qui l'incluent, avec des risques de conflits de noms.

Le fichier source .cpp


#include "LibraryCard.hpp"
#include <iostream>
using namespace std;

LibraryCard::LibraryCard(string newOwner)
    : owner(newOwner), borrowedBooks(0) {
}

bool LibraryCard::borrowBook() {
    if (borrowedBooks >= 5) {
        return false;
    }
    borrowedBooks++;
    return true;
}
  • Les guillemets désignent un fichier de votre projet, les chevrons < > la bibliothèque standard
  • LibraryCard:: devant chaque méthode indique sa classe. :: est l'opérateur de résolution de portée

bool LibraryCard::returnBook() {
    if (borrowedBooks == 0) {
        return false;
    }
    borrowedBooks--;
    return true;
}

int LibraryCard::getBorrowedBooks() const {
    return borrowedBooks;
}

void LibraryCard::display() const {
    cout << owner << " : " << borrowedBooks;
    cout << " livre(s)" << endl;
}
  • const se répète dans la définition
  • borrowedBooks-- retire 1

Copie ou référence ?


#include <iostream>
using namespace std;

class Wallet {
private:
    int coins = 10;

public:
    void spend(int amount) {
        coins = coins - amount;
    }
    int getCoins() const {
        return coins;
    }
};
  • Par défaut, un paramètre reçoit une copie : buyCoffeeCopy modifie la copie, l'original ne bouge pas
  • Avec &, le paramètre est une référence : un autre nom pour le même objet

void buyCoffeeCopy(Wallet wallet) {
    wallet.spend(2);
}

void buyCoffee(Wallet& wallet) {
    wallet.spend(2);
}

int main() {
    Wallet manonWallet;
    buyCoffeeCopy(manonWallet);
    cout << manonWallet.getCoins() << endl;
    buyCoffee(manonWallet);
    cout << manonWallet.getCoins() << endl;
    return 0;
}

La référence constante

void showWallet(const Wallet& wallet) {
    cout << wallet.getCoins() << endl;
    // wallet.spend(2);   ← refusé
}
  • Pour une fonction qui ne fait que lire un objet : une référence constante, const Wallet&
  • Pas de copie, et le compilateur garantit que l'objet n'est pas modifié. Seules les méthodes const sont permises

    void lendNotesTo(Student& classmate) {

            classmate.notes++;
        }
